# AME i18n 翻译维护指南

本文面向开发者，说明 AME 的界面翻译资源如何提取、编辑、编译和嵌入。当前中文是源语言，英文资源为 `en_US`；用户语言偏好在重启软件后生效。

## 资源结构

```text
sources.lst                              Qt lupdate 的唯一源码清单
app/common/i18n.py                       启动时解析语言并安装译者
app/resource/i18n/ame_en_US.ts           英文源翻译表，由 Qt Linguist 编辑
app/resource/i18n/ame_en_US.qm           lrelease 编译的英文翻译
app/resource/resource.qrc                应用图片、样式和 QM 的统一资源清单
app/common/resource.py                   rcc 生成文件，禁止手工修改
```

AME 文案直接以中文字符串作为 Qt 翻译源文本。英文模式加载嵌入的 `ame_en_US.qm`；加载失败时软件回退为简体中文。`resource.py` 将 QM 嵌入程序，因此运行时不依赖外置 TS/QM 文件。

## 在代码中标记翻译文本

Qt 控件和 `QObject` 派生类优先使用 `self.tr("中文文案")`。普通 Python 服务使用固定上下文调用 `QCoreApplication.translate("ClassOrFeature", "中文文案")`。上下文是翻译表中的定位信息，应保持稳定，并确保调用位置包含在 `sources.lst`。

```python
from PySide6.QtCore import QCoreApplication

message = QCoreApplication.translate("WorkflowService", "工作流保存失败")
```

类元数据等需要在模块载入时保留原中文值、稍后再显示的字符串，使用 `QT_TRANSLATE_NOOP` 标记供 `lupdate` 提取：

```python
from PySide6.QtCore import QT_TRANSLATE_NOOP

NODE_NAME = QT_TRANSLATE_NOOP("AMENodes", "我的节点")
```

节点显示层在 `AMENodes` 上下文中查找译文。不要在类定义时把译文写进 `NODE_NAME`、节点类型、端口名或 `set_name()`；这些原始值会用于工作流注册和旧文件兼容。

## 维护翻译的步骤

在仓库根目录的 PowerShell 中执行以下命令。工具使用项目 `.venv` 中安装的 PySide6。

### 1. 更新源码清单

新文案所在的页面、组件或服务需要列入 `sources.lst`。每行一个相对仓库根目录的源码路径；不要添加 `.venv`、生成的 `resource.py` 或第三方代码。节点文件需加入清单，否则其中的文案不会进入 TS。

### 2. 从源码提取或更新 TS

```powershell
.\.venv\Scripts\pyside6-lupdate.exe '@sources.lst' -source-language zh_CN -target-language en_US -locations relative -ts .\app\resource\i18n\ame_en_US.ts
```

在 Qt Linguist 编辑待翻译条目：

```powershell
.\.venv\Scripts\pyside6-linguist.exe .\app\resource\i18n\ame_en_US.ts
```

保留合理的历史条目。更新后检查上下文、重复源文本和消失的条目；每条确认后的英文译文都应标记为完成。

### 3. 检查并生成 QM

```powershell
.\.venv\Scripts\pyside6-lrelease.exe -fail-on-unfinished -fail-on-invalid .\app\resource\i18n\ame_en_US.ts -qm .\app\resource\i18n\ame_en_US.qm
```

严格编译会拒绝未完成或无效条目。人工核对 Python 格式占位符（如 `{name}`、`{count}`）、文件过滤器和上下文复用。Qt 编译检查无法替代对 Python `.format()` 占位符的核对。

### 4. 更新 QRC 生成的 Python 资源

修改 TS 后必须重新生成统一资源，即使 `resource.qrc` 未变化。增加新语言时，先把 QM 文件登记到 QRC。

```powershell
.\.venv\Scripts\pyside6-rcc.exe .\app\resource\resource.qrc -o .\app\common\resource.py
```

不要手工编辑 `resource.py`。提交时源码、`sources.lst`、TS、QM、QRC 和生成的资源模块应保持同步。

### 5. 启动检查

在设置页选择 English，退出并重新启动软件，检查改动涉及的页面、弹窗、节点标题、搜索菜单、错误提示和展开布局。译者在主窗口创建前安装，因此语言变化需重启。

```powershell
.\.venv\Scripts\python.exe .\AutoMediaEncode.py
```

## 新增一种语言

新增语言除了翻译 TS，还需要把语言选项、启动时的译者加载和 QM 资源一起接入。下面以日语 `ja_JP` 为例；新增其他语言时，按 Qt locale 替换示例中的 `ja_JP`，设置项使用连字符形式 `ja-JP`。

### 1. 建立新语言 TS 并完成翻译

先复制现有英文 TS 作为结构参考，或直接让 `lupdate` 从源码生成新文件。源码中文仍是唯一源语言，`sources.lst` 继续共用，不需要为每种语言维护另一份清单。

```powershell
Copy-Item .\app\resource\i18n\ame_en_US.ts .\app\resource\i18n\ame_ja_JP.ts
.\.venv\Scripts\pyside6-lupdate.exe '@sources.lst' -source-language zh_CN -target-language ja_JP -locations relative -ts .\app\resource\i18n\ame_ja_JP.ts
.\.venv\Scripts\pyside6-linguist.exe .\app\resource\i18n\ame_ja_JP.ts
```

检查每个上下文中的翻译、复数条目和格式占位符；不要翻译节点类型、端口名、配置键、CLI 参数等业务值。确认新语言条目均已完成后编译：

```powershell
.\.venv\Scripts\pyside6-lrelease.exe -fail-on-unfinished -fail-on-invalid .\app\resource\i18n\ame_ja_JP.ts -qm .\app\resource\i18n\ame_ja_JP.qm
```

### 2. 将语言接入设置选项

在 `app/common/config.py` 的 `cfg.language` 选项中加入 `ja-JP`。在 `app/view/setting_interface.py` 的 `languageCard` 中加入对应的用户可读名称（例如 `日本語`）；`texts` 顺序必须与 `OptionsValidator` 中的选项顺序一致，`Auto` 项仍显示“系统默认”。设置值是供程序判断的稳定键，显示名称才是本地化文字。

### 3. 接入启动时的语言解析和译者加载

在 `app/common/i18n.py` 中完成以下改动：

- 让 `resolve_language()` 将 `ja-JP` 映射为 Qt locale `ja_JP`。
- 如果希望“系统默认”可自动选中日语，在 `Auto` 分支识别系统 locale 的日语并返回 `ja_JP`。当前实现只在中文系统选中文，其余系统均选英文；不扩展该分支时，用户仍可手动选择日语。
- 让 `install_translations()` 为 `ja_JP` 加载 `:/app/i18n/ame_ja_JP.qm`，并把相应的 `QTranslator` 安装到应用。当前代码只为 `en_US` 加载 AME QM，因此仅添加 TS/QM 文件并不会让日语界面生效。
- 复用现有的 FluentTranslator 流程，为日语构造 `FluentTranslator(QLocale("ja_JP"), parent=app)`。QM 加载失败时记录错误并按既有约定回退简体中文；`ameLanguage` 属性应记录实际生效的 locale。

修改后要确认启动发生在创建主窗口之前，且译者对象在应用运行期间保持存活。若 `ameLanguage` 被服务层用于生成语言相关内容，也要检查该功能对新 locale 的行为；例如 MediaInfo 详细报告目前只在简体中文时启用中文报告，其他语言使用英文报告。

### 4. 登记 QM 并重新生成资源

在 `app/resource/resource.qrc` 中加入新 QM，沿用现有 `app` 资源前缀，运行时资源路径应为 `:/app/i18n/ame_ja_JP.qm`。再重新生成 `app/common/resource.py`：

```xml
<file>i18n/ame_ja_JP.qm</file>
```

```powershell
.\.venv\Scripts\pyside6-rcc.exe .\app\resource\resource.qrc -o .\app\common\resource.py
```

`resource.py` 是生成文件，不手工编辑。交付时需同步提交新 TS、QM、QRC 和生成的资源模块。

### 5. 验证新语言和回退路径

在设置中选择新语言并重启，检查设置项显示、常用页面、弹窗、节点菜单/标题、文件过滤器、错误提示和布局。再检查 `Auto`（如果已加入自动识别）、AME QM 缺失或加载失败时的回退，以及 MediaInfo 等读取 `ameLanguage` 的服务行为。确认旧有 `zh-CN`、`en-US` 和 `Auto` 仍按预期工作。

## 数据值与界面文案的边界

只翻译面向用户阅读的显示文案。工作流 JSON 和业务逻辑使用的值应保持原样，例如节点类型、`MENU_KEY`、端口名、属性键、编码器和容器标识、CLI 参数、轨道语言代码、外部工具原始输出以及用户填写的文件名/节点名。

若下拉项要翻译显示文字，同时保留原值，请把原值保存为 Qt item 的 `userData`，业务逻辑读取原值而非显示文字。界面中的“是/否”等文字也不应直接用作命令参数或布尔判断。

`QT_TRANSLATE_NOOP(context, text)` 用于静态元数据标记，不执行运行时翻译。运行时显示时仍需调用 `QCoreApplication.translate(context, text)`。上下文变化会导致旧翻译无法命中，应谨慎调整。

## AME 节点翻译约定

- 节点默认名称和描述使用 `QT_TRANSLATE_NOOP("AMENodes", ...)`；显示层查询译文，存档中的默认原文保持稳定。
- 节点公共控件使用一致的翻译上下文；与普通 Python 辅助类相关的文案使用固定上下文的 `QCoreApplication.translate()`。
- 节点菜单的中文源标签使用 `QT_TRANSLATE_NOOP("AMENodePalette", ...)`，运行时构建菜单时调用相同上下文翻译。
- 文件过滤器应翻译类别描述，再拼入程序生成的扩展名列表；扩展名本身不翻译。
- 用户自定义名称、节点说明文字和用户工作流文件名原样显示。
- 对带数量的英文消息使用 Qt numerus / `%n` 复数形式，不要手工拼接单复数。

## 语言行为

语言偏好为 `zh-CN`、`en-US` 或 `Auto`。`Auto` 会按系统语言选择中文或英文。AME 英文 QM 加载失败时启动会记录错误并回退中文。Fluent Widgets 的译者也由 `app/common/i18n.py` 在创建主窗口前安装。Windows 原生文件对话框和 Qt 自身部分原生控件的语言由系统决定。

可参考仓库维护笔记 `.Note/i18n_maintenance.md` 的实现历史；对外开发文档以本文件的当前流程为准。
