# AME 节点开发指南

本文面向 AME 工作流节点开发者，介绍节点结构、执行契约、注册方式和动态端口要点。当前实现基于 NodeGraphQt 0.6.44、PySide6 与 qfluentwidgets，应用仅支持 Windows。

## 代码位置

```text
app/components/ame_workflow/
  nodes/
    _base.py             AMENodeBase、端口/分类颜色及属性读取
    _widgets.py          可复用节点控件
    _helpers.py          编码、FFmpeg 参数和进程辅助逻辑
    __init__.py          节点导入、注册清单与菜单键映射
    system/ io/ process/ encoder/ muxer/
  node_palette.py        右键节点菜单结构
app/services/ame_workflow/
  workflow_executor.py   QThread 执行器、拓扑排序和端口数据传递
  process_runner.py      子进程、暂停和取消控制
  workflow_serializer.py 工作流读写适配
  ame_preset_service.py  内置和用户工作流管理
```

当前在 `ALL_NODE_CLASSES` 中注册 22 个节点类。节点的 `__identifier__` 使用固定命名空间 `ame`，节点类型名和端口名是工作流文件的一部分，应保持稳定。

## 节点基类和六段结构

继承 `AMENodeBase`。基类会建立 AME 视图、标题/说明、分类颜色、静态输入输出端口，并调用 `_setup_widgets()`。

```python
from pathlib import Path
import shutil
from PySide6.QtCore import QCoreApplication, QT_TRANSLATE_NOOP
from .._base import AMENodeBase, C, P
from .._widgets import FileBrowseWidget


class MyNode(AMENodeBase):
    # 1. 元信息：用于显示的原始中文字符串也是翻译源键
    NODE_NAME = QT_TRANSLATE_NOOP("AMENodes", "我的节点")
    DESCRIPTION = QT_TRANSLATE_NOOP("AMENodes", "读取文件并生成结果")
    CATEGORY = "工具"
    CATEGORY_COLOR = C["Orange"]
    MENU_KEY = "my_node"  # 唯一键

    # 2. 静态端口：(端口名, RGB 颜色)
    INPUTS = [("input", P["any"])]
    OUTPUTS = [("output", P["any"])]

    # 3. 不覆写 __init__：基类负责初始化端口和控件

    # 4. 内嵌控件。widget name 同时是节点 property 键
    def _setup_widgets(self):
        self.add_custom_widget(
            FileBrowseWidget(self.view, "source_path", QCoreApplication.translate("AMEWorkflowWidgets", "选择文件"))
        )

    # 5. 动态端口：仅在节点需要根据文件/上游信息改变端口时实现

    # 6. 执行逻辑
    def execute(self, inputs: dict, temp_dir: str) -> dict | None:
        source = self.property("source_path", "")
        if not source:
            self._last_error = QCoreApplication.translate("AMENodes", "请选择输入文件")
            return None
        # 示例：复制到缓存目录，并返回与 OUTPUTS 对应的端口键
        destination = Path(temp_dir) / Path(source).name
        shutil.copy2(source, destination)
        return {"output": [str(destination)]}
```

### `execute()` 数据契约

```python
execute(inputs: dict, temp_dir: str) -> dict | None
```

- `inputs` 的形状为 `{输入端口名: [上游文件路径, ...]}`。执行器根据连线收集上游 `execute()` 返回的路径。
- 返回 `dict` 表示成功；键必须是本节点输出端口名。空字典 `{}` 也表示成功且无文件输出。
- 返回 `None` 表示失败，执行器停止后续节点。把适合用户查看的失败原因写入 `self._last_error`。
- `temp_dir` 是执行器解析出的缓存目录。中间文件写入此目录，避免散落在源文件旁边。
- 文件操作前后检查取消状态。长任务应使用 `app.services.ame_workflow.process_runner` 的执行函数或检查 `check_cancelled()`，不要启动无法停止的后台子进程。

执行器在 QThread 中按拓扑顺序逐节点调用 `execute()`，并通过输出端口名把结果传给下游。连接中的循环依赖会阻止工作流执行。唯一的输出节点最后执行；工作流开始前要求至少有一个启用的输出节点，且不能多于一个。

### 节点属性和控件

控件的 `name` 是节点 property key；属性会进入工作流 JSON。属性值应为 JSON 可序列化的字符串、数字、布尔值、列表或字典。读取可用 `self.property(key, default)`，该包装会在缺少属性时返回默认值。

`_widgets.py` 提供文件、多文件、目录选择，下拉框、开关、复选框、动作按钮、预设与 CLI 文本控件。优先复用这些控件，保持属性回写及工作流保存行为一致。不要把控件赋给 `self._label`；该名称由基类保留为标题字符串。对于 mkvmerge 的轨道设置，请参考其节点专用布局补丁，不要修改 `_base.py` 的全局布局来迁就单个节点。

## 端口和颜色

端口名用稳定、简短的语义标识，例如 `video`、`audio`、`subtitle` 或带序号的 `video_1`。视频、音频、字幕、章节、附件、脚本管道和通用文件应分别使用 `_base.py` 中的 `P` 颜色。节点分类色使用 `C`。

视频编码器可有 `file` 和 `pipe` 两个输入：普通媒体走文件端口，VSPipe 数据走脚本管道端口。复用编码逻辑时应调用 `_helpers.py` 中已有的实现，避免同一 CLI 规则分散在多个节点文件。

## 动态端口

动态端口适用于探测轨道数后才知道 I/O 端口的节点。添加端口使用 `add_input()` 或 `add_output()`；删除前先断开连接，再调用 `delete_input()` 或 `delete_output()`。需要允许删除的节点调用 `set_port_deletion_allowed(True)`。

需要检查以下情况：

1. 保存和重新加载后端口名称、颜色、连接和控件设置都能恢复。
2. 删除动态端口时，其旧连线同时清理。
3. 文件探测耗时较长时使用工作线程，并避免旧请求覆盖新请求。
4. 分离器端口根据实际探测结果生成；不要假设端口固定只有 `video_1` 和 `audio_1`。
5. mkvmerge 节点动态增加轨道时，还要创建对应的轨道设置控件并恢复序号。

可参考 `nodes/process/splitter_node.py`、`nodes/io/input_video_normalizer_node.py`、`nodes/io/input_bd_normalizer_node.py` 和 `nodes/muxer/mkvmerge_muxer_node.py`。

## 注册新节点

1. 在合适的 `nodes/` 子目录新增节点类，并按六段结构实现。
2. 在 `nodes/__init__.py` 导入节点并加入 `ALL_NODE_CLASSES`。`MENU_KEY_MAP` 会由该列表生成。
3. 在 `node_palette.py` 的 `NODE_PALETTE_STRUCTURE` 加入菜单项，菜单目标字符串必须与节点 `MENU_KEY` 一致。
4. 把新源码文件加入仓库根目录 `sources.lst`，以便提取该节点中的 Qt 翻译文本。
5. 按 [AME i18n 翻译维护指南](AME-i18n翻译维护指南.md) 更新翻译资源。
6. 逐项检查节点创建、连接、保存/加载以及执行数据契约。仓库当前没有自动化测试套件；提交说明应明确记录手动检查范围。

## 执行和缓存注意事项

- 除输出节点外，没有参与任何连线的孤立节点不会自动执行；执行器按拓扑顺序运行已连线节点。输出节点最后执行。
- 禁用节点不会旁路。如果启用节点依赖禁用上游，执行会在文件操作开始前报错；错误文案可用 `display_name()` 获取当前语言的默认节点名称。
- 工作区节点优先确定 `temp_dir`，其次尝试输出目录，再尝试输入文件目录。不要清理任意路径。
- 输出节点的缓存清理仅在完整成功后进行，并校验只删除名为 `temp` 的工作区子目录；取消或失败时保留缓存。
- 工具路径通过 `ToolService` 解析。用 `subprocess.CREATE_NO_WINDOW`，并复用 `process_runner` 的取消与暂停机制。
- 用户可见字符串使用 Qt 翻译；节点类型、MENU_KEY、端口名、属性键、预设键和 CLI 参数保持稳定，不应使用翻译后的值作为数据键。
